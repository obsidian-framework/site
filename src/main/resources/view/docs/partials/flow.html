Flow (Navigation)

Flow is a client-side navigation system that intercepts link clicks and form submissions to perform AJAX-based page transitions without full reloads. It automatically re-initializes LiveComponents and re-executes scripts after each navigation.

How it works

Flow is initialized automatically on page load. It attaches three global listeners:

  • • click — intercepts <a> tag navigation (same-origin only)
  • • submit — intercepts GET and POST form submissions
  • • popstate — handles browser back/forward buttons
Including Flow in your templates

Use the {{ flow_scripts }} global variable in your base Pebble template to inject the Flow script tag. The variable is provided automatically — no manual registration needed. The | raw filter is required, otherwise Pebble escapes the tag and renders it as plain text. 

<!DOCTYPE html>
<html>
<head>
    <title>My App</title>
</head>
<body>
    {% block content %}{% endblock %}

    {{ flow_scripts | raw }}
</body>
</html>
💡 Cache busting

In production, the script is served as flow.js?v=1.0.0. In all other environments, the current timestamp is used — forcing the browser to re-fetch the script on every restart.

Opting out

Add data-flow="false" to any link or form to bypass Flow and trigger a standard full-page navigation instead. 

<!-- Standard AJAX navigation (default) -->
<a href="/dashboard">Dashboard</a>

<!-- Full page reload -->
<a href="/download/report.pdf" data-flow="false">Download PDF</a>

<!-- Form opt-out -->
<form action="/upload" method="post" data-flow="false">
    <input type="file" name="file">
    <button type="submit">Upload</button>
</form>
Listening to navigation events

Flow dispatches a obsidian:flow:load event on window after every successful navigation. Use it to run custom logic (analytics, UI resets, etc.) without touching the core system. 

window.addEventListener('obsidian:flow:load', (event) => {
    console.log('Navigated to:', event.detail.url);

    // Re-initialize third-party libraries
    hljs.highlightAll();
    // Track page views
    analytics.page(event.detail.url);
});

// Detect POST → GET redirects
window.addEventListener('obsidian:flow:redirect', (event) => {
    console.log('Redirected from', event.detail.from, 'to', event.detail.to);
});
Programmatic navigation

You can navigate programmatically via the global window.ObsidianFlow instance. 

// Simple GET navigation
window.ObsidianFlow.navigate('/profile');

// Without pushing to browser history
window.ObsidianFlow.navigate('/modal-content', { pushState: false });

// POST navigation with FormData
const data = new FormData();
data.append('username', 'alice');
window.ObsidianFlow.navigate('/login', { method: 'POST', body: data });
Per-link timeout

The global fetch timeout is 8000ms. Override it on a per-link basis via data-flow-timeout for routes that are known to be slower. 

<a href="/export/report" data-flow-timeout="15000">Export report</a>
Customizing the progress bar

The progress bar color is controlled via a CSS variable. Override it anywhere in your stylesheet. 

:root {
    --obsidian-flow-color: #6366f1; /* indigo */
}
Path conventions

Flow skips same-page anchor links automatically. Avoid naming HTTP routes the same as WebSocket endpoints — use the /ws/ prefix for WebSocket paths to prevent conflicts. 

// ✅ No conflict — Flow intercepts /chat, WebSocket is on /ws/chat
@GET("/chat")
@WebSocket("/ws/chat")

// ❌ Conflict — Flow and WebSocket fight over the same path
@GET("/chat")
@WebSocket("/chat")
Prefetch & server-side detection

Flow prefetches links on hover to reduce perceived navigation latency. Prefetch requests include the X-Obsidian-Prefetch: 1 header so the server can skip side effects while still enforcing security checks. 

@GET("/dashboard")
public void dashboard(Request req, Response res) throws IOException {
    if (!req.attribute("prefetch")) {
        analytics.trackPageView(req);
    }
    res.render("dashboard.html");
}
API reference
Method / Property / Event Type Description
navigate(url, options?) Promise<void> Navigates to the given URL. Options: pushState (bool), method (string), body (FormData), timeout (number).
navigating boolean True while a navigation fetch is in progress.
currentUrl string The URL of the last successfully loaded page.
timeout number Global fetch timeout in milliseconds. Default: 8000. Override per link via data-flow-timeout.
obsidian:flow:load CustomEvent Dispatched on window after each navigation. Detail: { url: string }.
obsidian:flow:redirect CustomEvent Dispatched on window when a POST navigation lands on a different URL. Detail: { from: string, to: string }.
💡 Important

Add data-flow="false" on any link or form that must trigger a full reload — file uploads, external redirects, or OAuth flows.

  • • Forms with live:submit are skipped automatically — handled by LiveComponents
  • • External links are never intercepted regardless of data-flow
  • • Override --obsidian-flow-color to match your brand
